## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加网址并在侧栏标签页浏览 (Priority: P1)

作为频繁处理多个网页工具的用户，我希望把常用网页保存到扩展侧栏，并在侧栏内像手机浏览器一样打开、切换和关闭页面，以便在不占用主窗口的情况下处理多个页面。

**Why this priority**: 网站添加、标签页浏览和侧栏内使用是产品核心价值；没有它们，移动标识、登录复用和悬停菜单都没有可用入口。

**Independent Test**: 可通过添加两个合法网址、创建并切换标签页、关闭标签页和重新打开侧栏完整验证；该切片本身就能提供多网页侧栏浏览价值。

**Acceptance Scenarios**:

1. **Given** 侧栏打开，**When** 用户添加一个合法的 `http` 或 `https` 网址，**Then** 该网址保存到网站列表、新标签页立即打开并成为当前标签。
2. **Given** 用户输入特殊协议或非法 URL，**When** 用户尝试添加，**Then** 系统拒绝添加、说明原因，且网站列表与标签历史不产生新记录。
3. **Given** 用户打开多个标签页，**When** 用户切换、关闭或刷新标签页，**Then** 每个标签页保持自己的当前 URL、加载状态和 URL 历史。
4. **Given** 某个标签页关闭，**When** 用户重新启动扩展，**Then** 该关闭标签页不会恢复，其他未关闭标签页和网站列表仍可用。

---

### User Story 2 - 在侧栏中获得移动端适配 (Priority: P2)

作为在窄侧栏中浏览网页的用户，我希望网页默认按移动端方式适配，并能为某个网站切换桌面模式或真实移动 User-Agent，以便网页布局和内容尽量适合侧栏空间。

**Why this priority**: 移动端适配是项目与普通收藏夹或标签管理工具的主要差异；User-Agent 是产品承诺的一部分，但必须避免把降级行为伪装成真实移动请求。

**Independent Test**: 可通过同一网站分别使用默认移动视口、启用真实移动 User-Agent 并切换桌面模式验证；即使其他标签页和登录复用未实现，该故事仍能独立展示移动适配价值。

**Acceptance Scenarios**:

1. **Given** 用户打开尚未授权真实移动 User-Agent 的站点，**When** 页面加载，**Then** 系统使用移动视口适配，并明确显示当前不是已确认的真实移动 User-Agent。
2. **Given** 用户为某个精确来源开启真实移动 User-Agent，**When** 权限申请成功并重新加载，**Then** 系统尝试以移动 User-Agent 请求，并显示真实能力状态。
3. **Given** 用户拒绝或浏览器不支持真实移动 User-Agent，**When** 页面继续加载，**Then** 系统保留移动视口、显示“已降级/未启用”，且不宣称服务器收到移动标识。
4. **Given** 用户将某个精确来源切换为桌面模式，**When** 该来源的当前标签页重新加载或新建标签页打开，**Then** 系统按保存的桌面模式处理，其他来源不受影响。

---

### User Story 3 - 按站点复用登录状态 (Priority: P3)

作为需要频繁访问登录型网页工具的用户，我希望只对明确授权的网站尝试复用浏览器登录状态，并在失败时清楚看到原因，以便减少重复登录，同时不扩大不必要的权限。

**Why this priority**: 登录复用显著影响日常体验，但涉及敏感能力，必须排在基础浏览和移动端适配之后，并采用按需、按来源、可撤销的授权。

**Independent Test**: 可通过一个可嵌入的登录测试页面验证授权前、授权成功、授权失败和撤销授权四种状态；不要求其他故事同时存在。

**Acceptance Scenarios**:

1. **Given** 用户尚未为某个精确来源开启登录复用，**When** 页面需要登录，**Then** 系统显示未授权状态，不申请相关权限。
2. **Given** 用户为该精确来源开启登录复用并批准权限，**When** 页面重新加载，**Then** 系统按浏览器允许的 Cookie 规则尽力复用登录状态。
3. **Given** 登录复用受到 Cookie 属性、第三方 Cookie、隐私策略或网站限制影响，**When** 页面未保持登录，**Then** 系统显示失败或受限状态，并提供重新登录或普通标签页打开操作。
4. **Given** 用户关闭该来源的登录复用，**When** 当前标签页刷新，**Then** 系统停止使用该授权能力、撤销对应可选权限并清理授权标记。

---

### User Story 4 - 处理不可嵌入、新窗口和复杂导航 (Priority: P4)

作为会在网页内继续点击链接的用户，我希望扩展尽量跟随网页导航，并在不可嵌入或浏览器安全边界阻止操作时给出可理解的选择，以便不打断当前工作流。

**Why this priority**: 该故事覆盖真实网站的兼容边界，能显著降低“打开失败”或“离开后丢失上下文”的挫败感。

**Independent Test**: 可使用禁止嵌入页面、可嵌入但跨来源导航页面、单页应用 URL 变化和请求新窗口页面分别验证。

**Acceptance Scenarios**:

1. **Given** 目标网站禁止 iframe 嵌入，**When** 加载失败，**Then** 侧栏保留当前标签页，显示失败状态，并提供当前标签页或新标签页打开。
2. **Given** iframe 发生可观察的链接导航或单页应用 URL 变化，**When** URL 或标题更新，**Then** 系统更新当前标签页历史、标题和状态。
3. **Given** 跨来源内部状态无法读取，**When** 用户使用前进或后退，**Then** 系统优先使用可观察导航，否则使用扩展保存的 URL 历史重新加载，并明确显示可能不同步。
4. **Given** 网页请求新窗口或新标签页，**When** 系统能识别该请求，**Then** 系统尽力转成扩展内新标签页；无法识别或拦截时提供降级操作且不丢失用户点击。
5. **Given** 网页导航到一个尚未添加的精确来源，**When** 新来源加载，**Then** 系统自动将该来源加入网站列表并保留当前路径作为入口。

---

### User Story 5 - 重启后恢复浏览会话 (Priority: P5)

作为跨多次浏览器会话使用侧栏的用户，我希望扩展重新加载后能恢复之前的网站、标签页和浏览历史，以便不需要重新整理工作现场。

**Why this priority**: 会话恢复提升连续使用价值，但它依赖前面的标签页、网站列表和导航模型。

**Independent Test**: 可通过创建多个标签页、产生历史、关闭扩展或浏览器后重新打开验证恢复结果。

**Acceptance Scenarios**:

1. **Given** 用户存在多个标签页和网站条目，**When** 扩展重新启动，**Then** 系统恢复网站列表、打开的标签页、活动标签、每个标签页最多 100 条 URL 历史和站点设置。
2. **Given** 恢复的 URL 无法加载，**When** 系统恢复会话，**Then** 标签页和历史仍保留，并显示重试或普通标签页打开操作。
3. **Given** 部分持久化记录损坏，**When** 系统读取会话，**Then** 系统按记录粒度丢弃无效数据，不因一条坏记录阻塞整个侧栏启动。
4. **Given** 页面包含表单、密码或临时脚本状态，**When** 系统恢复会话，**Then** 系统只重新加载 URL，不恢复页面内容、密码或表单输入。

---

### User Story 6 - 使用紧凑且可访问的侧栏操作 (Priority: P6)

作为经常在鼠标、触摸和键盘之间切换的用户，我希望侧栏界面用紧凑标签栏和可展开的图标子菜单呈现操作，以便在有限空间中高效使用并保持可访问性。

**Why this priority**: 交互效率是侧栏产品的关键体验，但依赖前面的标签页、网站和设置能力。

**Independent Test**: 可通过窄侧栏下打开多个标签页，分别用鼠标悬停、触摸点击和键盘操作打开、关闭和触发菜单功能验证。

**Acceptance Scenarios**:

1. **Given** 侧栏显示网站列表，**When** 用户打开一个网站，**Then** 网页内容占满侧栏，并通过返回或主页入口回到网站列表。
2. **Given** 用户存在多个标签页，**When** 标签栏空间不足，**Then** 系统保留紧凑标签栏，并通过标签列表菜单展示全部标签页。
3. **Given** 用户将鼠标悬停在标签页、导航、网站或站点设置图标上，**When** 菜单打开，**Then** 显示与上下文对应的操作；触摸点击或键盘聚焦/Enter 也能打开同一菜单。
4. **Given** 菜单已打开，**When** 用户按 Esc 或点击菜单外部，**Then** 菜单关闭且焦点或页面状态不会被意外破坏。
5. **Given** 用户只使用键盘或辅助技术，**When** 浏览菜单，**Then** 每个图标操作具有可访问名称和可用焦点状态。

---

### Edge Cases

- **URL 边界**：拒绝 `javascript:`、`data:`、`file:`、`chrome:`、`ftp:` 等特殊协议；对无效或不可解析的 URL 提示修正；保留用户原始输入以便编辑。
- **iframe 禁止嵌入**：显示可理解的原因和当前标签页/新标签页打开操作；不自动离开侧栏；失败 URL 不覆盖成功的历史记录。
- **真实 User-Agent 受限**：权限被拒绝、能力不可用或请求改写失败时，使用移动视口并标记“真实移动 UA 未启用”。
- **Cookie 边界**：Cookie 按浏览器规则受域名、路径、SameSite、Secure、第三方 Cookie、隐私防护和 Cookie 分区影响；扩展设置按协议、域名、端口记录，但不承诺端口级 Cookie 隔离。
- **跨来源不可观察**：扩展无法读取某些跨来源 iframe 的实时 URL、标题或内部历史时，地址和状态标记为“可能未同步”。
- **新窗口请求失败**：无法拦截或识别 `target="_blank"` / `window.open()` 时，不静默丢弃用户操作，并提供普通标签页或新标签页打开操作。
- **权限外部撤销**：用户从浏览器设置撤销权限后，扩展在下一次检查或使用时清理授权标记并回到降级模式。
- **历史容量**：每个标签页最多持久化 100 条 URL；超出后淘汰最旧记录，并保持前进/后退位置一致。
- **所有标签页关闭**：恢复时显示网站列表主页，不自动重建已删除的标签页。
- **存储损坏或配额不足**：尽可能保留当前可用数据；局部丢弃损坏记录；提示会话可能无法完整恢复，不暴露内部堆栈或敏感数据。
- **失败网站的安全提示**：降级页不渲染目标网站返回的原始 HTML，不把网页错误直接作为可执行内容显示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持在 Chrome MV3 与 Firefox 中打开扩展侧栏，并以侧栏作为添加网址、浏览网页和管理标签页的主界面。
- **FR-002**: 系统必须允许用户添加合法的 `http://` 和 `https://` URL，并在添加前校验协议、格式和可导航性。
- **FR-003**: 系统必须拒绝 `javascript:`、`data:`、`file:`、`chrome:`、`ftp:` 及其他非 `http/https` 地址，并给出用户可理解的原因。
- **FR-004**: 系统必须将添加的网址保存到网站列表，并立即创建或切换到新标签页打开该网址。
- **FR-005**: 系统必须按精确来源（协议、域名、端口）归并网站条目和站点设置；同一精确来源下的不同路径必须保留为可用入口。
- **FR-006**: 系统必须在 iframe 中加载网页；当网站禁止嵌入或加载失败时，必须在侧栏内显示降级状态和“当前标签页打开”“新标签页打开”操作。
- **FR-007**: 系统必须在网页视图默认使用移动视口适配，并明确区分移动视口与已确认的真实移动 User-Agent。
- **FR-008**: 系统必须允许每个精确来源保存“移动端”或“桌面端”模式；新增站点默认移动端，同来源新建标签页必须继承保存的模式。
- **FR-009**: 系统必须允许用户按精确来源单独开启真实移动 User-Agent；该能力必须与登录复用授权分开管理。
- **FR-010**: 系统必须在用户开启真实移动 User-Agent 时按需申请相关可选权限；授权成功后才尝试真实 UA，未授权或失败时必须退回移动视口并显示实际状态。
- **FR-011**: 系统必须允许用户按精确来源单独开启登录状态复用；该能力必须与真实移动 User-Agent 授权分开管理。
- **FR-012**: 系统必须在用户开启登录复用时按需申请相关可选权限，并只在浏览器 Cookie 规则允许的范围内尽力复用登录状态。
- **FR-013**: 系统必须在用户关闭任一授权时立即撤销对应可选权限、清理授权标记，并使当前相关标签页回到未授权或降级模式。
- **FR-014**: 系统必须支持多个标签页；每个标签页必须拥有独立的当前 URL、加载状态、前进/后退历史、刷新和关闭操作。
- **FR-015**: 系统必须为每个标签页持久化完整 URL 历史栈和当前位置，每个标签页最多保留 100 条 URL，超出时淘汰最旧记录。
- **FR-016**: 系统必须在标签页关闭时从持久化会话中删除该标签页及其历史；若所有标签页都关闭，恢复时必须显示网站列表主页。
- **FR-017**: 系统必须在扩展关闭或重新加载后恢复网站列表、打开的标签页、活动标签、站点设置和每个标签页的 URL 历史。
- **FR-018**: 系统恢复会话时必须重新加载 URL，不得持久化或恢复页面内容、密码、表单输入、临时脚本状态或 Cookie 值。
- **FR-019**: 系统必须在网页导航时自动加入新的精确来源，并将当前路径保留为该来源的入口；不覆盖已有的用户保存入口。
- **FR-020**: 系统必须尽力追踪 iframe 中可观察的链接导航、跨来源导航、单页应用 URL 变化和标题变化，并更新当前标签页状态。
- **FR-021**: 当 iframe 的跨来源内部 URL、标题或导航状态不可读取时，系统必须显示“可能未同步”或等价状态，不得伪造精确状态。
- **FR-022**: 系统的前进和后退必须优先使用当前可观察的 iframe 导航；不可观察时必须使用扩展保存的 URL 历史重新加载，并保持历史位置一致。
- **FR-023**: 系统必须尽力将 `target="_blank"` 和可识别的 `window.open()` 请求转换为扩展内新标签页；无法识别或拦截时必须保留用户操作并提供降级打开。
- **FR-024**: 系统必须在网页视图中使用紧凑标签栏显示图标和截断标题；标签页过多时必须提供标签列表菜单。
- **FR-025**: 系统必须采用网站列表主视图与网页内容单视图切换；进入网页后内容必须占满侧栏，网站列表不得常驻压缩网页区域。
- **FR-026**: 系统必须提供覆盖标签页操作、导航操作、网站管理和站点设置的上下文图标子菜单。
- **FR-027**: 图标子菜单必须支持鼠标悬停打开、触摸点击切换、键盘聚焦或 Enter 打开，并支持 Esc 或点击外部关闭。
- **FR-028**: 所有仅图标操作必须提供可访问名称、可见焦点状态和键盘可达性；交互不得只依赖悬停。
- **FR-029**: 系统必须显示每类能力的状态：可用、未授权、已降级、失败或不确定；不得将降级结果显示为成功。
- **FR-030**: 系统必须在权限被外部撤销或失效时自动清理扩展内授权标记，并在下一次使用或检查时回到降级模式。
- **FR-031**: 系统必须在会话数据损坏时按记录粒度丢弃无效数据，并保证其余可用数据仍能加载。
- **FR-032**: 系统必须在存储失败或配额不足时保留当前会话的可用操作，并提示数据可能无法完整持久化。
- **FR-033**: 系统不得保存、显示、传输或记录 Cookie 值、密码、表单输入或页面敏感内容。
- **FR-034**: 系统必须使用安全的文本渲染方式显示网页标题、URL 和错误状态，不得把外部内容当作可执行 HTML 渲染。
- **FR-035**: 系统必须在安装和更新后不主动申请所有可选权限；只有用户明确开启对应站点能力时才申请相关权限。
- **FR-036**: 系统必须允许用户在授权被拒绝后继续添加网址、浏览网页、使用移动视口和管理标签页。
- **FR-037**: 系统必须支持真实浏览器场景验收，至少覆盖可嵌入页面、禁止嵌入页面、登录型页面、跨来源导航页面、单页应用和新窗口请求页面。
- **FR-038**: 系统必须保证移动/桌面模式切换只影响当前精确来源，不影响其他网站或其他来源的标签页。
- **FR-039**: 系统必须保证 User-Agent 授权、Cookie 授权和移动/桌面模式在重新启动后仍按站点设置恢复，但不得把历史能力成功状态持久化为永久成功。
- **FR-040**: 系统必须在新窗口请求无法被安全转换时提供当前标签页或新标签页打开，不得静默阻止用户导航。

### Key Entities *(include if feature involves data)*

- **网站条目**: 用户保存的精确来源及其一个或多个入口 URL；关联站点名称、图标和默认显示模式。
- **精确来源**: 由协议、域名和端口组成的站点身份；用于网站归并、模式保存和授权设置。
- **浏览标签页**: 侧栏中的一次网页浏览实例；包含当前 URL、标题、加载状态、历史栈、当前位置和活动状态。
- **URL 历史项**: 某个标签页中的一条可恢复 URL；记录相对顺序，不包含页面内容或敏感输入。
- **站点设置**: 精确来源下的移动/桌面模式、真实移动 User-Agent 授权状态和登录复用授权状态。
- **能力状态**: 对某次或某类能力的可用性说明，包括可用、未授权、已降级、失败和不确定。
- **会话快照**: 重启前保存的网站列表、标签页集合、活动标签、历史栈和站点设置，不包含 Cookie 值或页面内容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 合法 `http/https` 网址的添加校验成功率达到 100%；添加后 100% 立即在侧栏新标签页打开或明确显示降级。
- **SC-002**: 95% 的用户在 3 次操作以内完成添加网址并打开新标签页；切换已有网站不超过 2 次操作。
- **SC-003**: 20 个标签页同时存在时，用户仍能定位活动标签、打开标签列表、关闭目标标签页并完成刷新，且操作不遮挡网页主要内容。
- **SC-004**: 对支持嵌入和移动适配的网站，80% 以上的测试页面默认呈现适合侧栏的移动布局或明确的降级状态。
- **SC-005**: 在权限被拒绝、能力不可用或网页限制导致降级时，100% 显示真实状态，不把移动视口、未授权或失败伪装成成功。
- **SC-006**: 在登录复用能力被浏览器允许的测试场景中，至少 80% 的已授权网站无需重新输入凭据即可恢复登录；不允许场景中 100% 给出可理解的重登录或普通标签页操作。
- **SC-007**: 扩展关闭或浏览器重启后，100% 恢复未关闭标签页、活动标签、网站列表、站点模式和每个标签页最多 100 条历史；关闭的标签页 0 个被恢复。
- **SC-008**: 常规添加网址、打开网站、切换标签页、切换模式和返回网站列表在支持设备上于 2 秒内呈现可用反馈或加载状态。
- **SC-009**: 禁止嵌入、跨来源不可观察、新窗口请求失败、权限外部撤销和存储损坏等测试中，100% 保持侧栏可继续操作且不产生浏览器级错误或数据损坏。
- **SC-010**: 使用鼠标、触摸和仅键盘操作时，100% 的图标子菜单可打开、可关闭、可触发对应操作，且每个操作具有可访问名称。
- **SC-011**: 在 Chrome MV3 和 Firefox 中，核心流程完成率均达到 100%；由于平台限制导致的差异均以明确状态显示，不出现未提示的功能缺失。
- **SC-012**: 功能数据持久化过程中，Cookie 值、密码、表单输入和页面内容的持久化记录数量为 0。

## Assumptions

- 用户使用支持扩展侧栏的现代 Chrome MV3 和 Firefox 环境，且已授予打开扩展侧栏所需的基础能力。
- “任意网址”指任意合法的 `http://` 或 `https://` URL；用户添加网址不代表目标网站允许 iframe 嵌入。
- 默认移动体验首先是移动视口；真实移动 User-Agent 是按需、按精确来源、最佳努力能力。
- Cookie 复用完全遵循浏览器 Cookie 规则；扩展设置按协议、域名、端口记录，但 Cookie 无法被扩展人为改造成端口级隔离。
- 扩展不提供服务器代理、远程渲染或绕过网站 `X-Frame-Options`/CSP 的能力。
- 表单自动填充、网页截图、下载管理、内容屏蔽和跨设备同步不属于首版范围。
- 每个标签页的历史持久化上限为 100 条 URL；超过后删除最旧记录，以保持恢复速度和存储量可控。
- 系统只持久化恢复现场所需的 URL、标签页、站点设置和状态，不持久化 Cookie 值、密码、表单输入、页面内容或敏感请求数据。
- 普通浏览器标签页可作为用户主动选择的降级目的地；系统不会未经用户操作自动把失败网页带出侧栏。
- 跨来源 iframe 的实时 URL、标题、内部历史和新窗口行为可能受浏览器安全边界限制；不可观察时产品必须明确标记不确定状态。
